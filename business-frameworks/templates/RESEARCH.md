<guidelines>

**Business Landscape:**
- Map the client's current reality before designing anything
- Be honest about gaps — this is where the value is
- Priority helps sequence the roadmap

**Industry Benchmarks:**
- Use real numbers when available, ranges when not
- "Industry average" gives the client context for where they stand
- Target should be ambitious but achievable in the engagement timeframe

**Existing Assets Audit:**
- Critical — never throw away what's working
- The 4 categories (working / partially working / not working / missing) prevent "start from scratch" bias
- Everything in "Working Well" is an asset to build on, not replace

**Tools & Stack:**
- Don't recommend tool changes unless the current tool is genuinely broken
- Migration cost is real — factor it into roadmap
- "Keep" is often the right answer even if a better tool exists

**Common Pitfalls:**
- Domain-specific, not generic project management advice
- Each pitfall should have a concrete avoidance strategy
- These inform constraints in the phase planning

**Implications for Roadmap:**
- This section directly feeds into ROADMAP.md creation
- Quick wins build client confidence early
- Risks inform contingency planning

</guidelines>
